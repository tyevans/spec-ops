# TASK-0048: Conventional Commit Slicing, Standardized RFC-822 Git Trailers, and Lineage Review Brief

## Summary
Implement automated conventional commit type derivation from task vertical slice metadata (`feat`, `refactor`, `spike`, `fix`), embedding standard RFC-822 git trailers (`SpecOps-Task`, `SpecOps-Slice`, `SpecOps-PRD`, `SpecOps-ADR`, `Provenance`) into squash commit messages. Provide the `spec-ops review <task-id> [--provenance]` CLI command to generate a structured PR review brief linking diffs directly to governing PRDs, ADRs, Gherkin scenarios, file length headroom, and author distinction.

## Problem Statement & Context
Commits generated by autonomous coding agents frequently lack semantic classification and structured provenance metadata, polluting git histories with generic messages ("agent commit") and breaking downstream semantic changelog tools. Human reviewers must manually piece together which PRD or ADR motivated a change and struggle to distinguish human commits from agent commits on collaborative branches, causing severe PR fatigue.

## User Stories & Scenarios Satisfied
- **US-0084: Conventional Commit Slice Classification and Standardized Git Trailer Lineage**
  - *Scenario: Deriving Conventional Commit Type from Task Slice Metadata*
  - *Scenario: Bug Fix and Refactoring Slice Commit Formatting*
- **US-0036: Context-Enriched Pull Request Review and Architectural Lineage**
  - *Scenario: Generating an architectural review brief for an agent PR*
  - *Scenario: Verifying commit provenance trailers and author distinction*

## Architectural Invariants & Seams
- **File Length Limit (<500 lines)**: Commit metadata engine in `src/spec_ops/worker/commits.py` and review generator in `src/spec_ops/worker/review.py` must stay strictly under 400 lines (ADR-0002).
- **Hypothesis Invariant Property (ADR-0009)**: Generative property tests using `@given(...)` across arbitrary task metadata dicts assert that generated commit subjects adhere to Conventional Commits 1.0 format and RFC-822 trailer format readable by standard git log tools.
- **Mutmut Mutation Scope**: Commit message generation and trailer formatting in `src/spec_ops/worker/commits.py` achieve >=80% mutant kill score under `mutmut`.

## Definition of Done (Blackbox Frontdoor TDD)
1. Squash-merge commits automatically derive conventional type based on task slice metadata (`feat`, `refactor`, `spike`, `fix`) and format subject as `<type>(<task-id>): <title>`.
2. Commit bodies embed valid RFC-822 trailers (`SpecOps-Task`, `SpecOps-Slice`, `SpecOps-PRD`, `SpecOps-ADR`, `Provenance`) verified by `git log -1 --pretty=full`.
3. Running `spec-ops review <task-id>` outputs a structured summary containing governing PRD, governing ADRs, acceptance scenarios, line deltas, file headroom, and verification status.
4. Running `spec-ops review <task-id> --provenance` distinguishes agent vs human authored commits and flags any commits missing the `SpecOps-Task` trailer.
5. All scenarios verified via public frontdoor `pytest-bdd` tests without private mock backdoors (ADR-0003, ADR-0006).
