# TASK-0176: Support Committing Debt Baseline File Without Gitignore Suppression

## Summary
The `.specops/` directory is ignored in `.gitignore` by default in SpecOps templates and repositories. However, `.specops/grandfathered_debt.json` is a core compliance and invariant artifact generated by `spec-ops adopt`. If `.specops/` is completely ignored, git refuses to commit the grandfathered debt baseline, meaning CI and other developers in a team will fail file length checks.

## Problem Statement & Context
1. In `spec-ops/.gitignore`:
   ```gitignore
   .specops/
   ```
2. When `spec-ops adopt` creates `.specops/grandfathered_debt.json`, running `git status` shows either untracked or ignored if `.specops/` is in `.gitignore`.
3. If an engineer attempts `git add .` or clones fresh on CI, `.specops/grandfathered_debt.json` is missing unless committed.
4. While `specops.toml` also mirrors file paths under `[invariants.file_limits]`, the exact line count limits reside in `grandfathered_debt.json`.

## Proposed Fix
1. In `.gitignore` templates and documentation, ensure `.specops/grandfathered_debt.json` is unignored:
   ```gitignore
   .specops/*
   !.specops/grandfathered_debt.json
   ```
   Or place `grandfathered_debt.json` in a directory intended for version control (such as `docs/project/` or root).

## Definition of Done (Blackbox Frontdoor TDD)
1. Verify `git add` and `git check-ignore` behave predictably for grandfathered debt files.
2. Invariant verification passes in clean CI checkout scenarios.
