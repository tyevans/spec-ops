# Explanation: Delivering Integrated Value and Preventing Functional Silos

This document explores how SpecOps avoids the "Silo of Mocked Perfection" and guarantees end-to-end integration across autonomous AI coding workflows.

For the comprehensive architectural treatise, see [`Delivering Real Integrated Value`](../delivering-real-value.md).

---

## The Failure Mode of Horizontal Layers

When multi-agent teams decompose software into horizontal layers (database tables, API controllers, frontend views):
- Each layer is authored in a separate work stream or agent session.
- Agents rely heavily on mocks to satisfy isolated unit tests.
- When layers are finally assembled, incompatible assumptions and contract mismatches cause widespread breakage.

---

## How SpecOps Enforces Integration

1. **Thin Vertical Slicing**: Every task generated by `spec-ops prd decompose` touches the necessary layers to complete one user-observable behavior.
2. **Blackbox Frontdoors**: Tests must invoke public interfaces (CLI, HTTP, domain events) rather than reaching into private internals.
3. **Executable Gherkin Scenarios**: The acceptance criteria of user stories are executed as integration tests.
4. **Relational Graph Lineage**: The `ProjectGraph` ensures no task is executed unless it traces back to an accepted User Story and PRD.
